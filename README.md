# CQA — Conversation Quality Analytics

Прототип системы оценки качества работы операторов Freedom Broker по чек-листу.
ИИ проверяет диалог (чат или звонок на RU / KZ / EN) по каждому критерию, указывает реплики-доказательства,
система детерминированно считает итог. Результат можно оспорить, проверяющий подтверждает или меняет
оценку, итог пересчитывается.

**Полностью локальное решение**: модель работает на своей видеокарте через [Ollama](https://ollama.com),
внешних платных API нет. Стоимость одной оценки — 0 ₽. Можно переключиться на любой
OpenAI-совместимый API (LM Studio, vLLM, облако) в настройках.

## Быстрый старт (Windows)

1. Установите Python 3.11+ и Ollama:
   ```powershell
   winget install Python.Python.3.12
   winget install Ollama.Ollama
   ```
2. Скачайте модель (≈ 5 ГБ, нужна видеокарта с 8 ГБ или 16 ГБ ОЗУ для CPU):
   ```powershell
   ollama pull qwen3:8b
   ```
3. Укажите ссылку на API организаторов (кнопка «Открыть GET для DEV» в задании) — одним из способов:
   - скопируйте `config.local.example.json` в `config.local.json` и вставьте ссылку в `org_api_url`;
   - или переменная окружения `CQA_ORG_API_URL`;
   - или после запуска: «Настройки» → «Источник данных».

   Подписанная ссылка не хранится в репозитории. Параметр `group_id` подставляется автоматически.
4. Запустите (первый запуск сам создаст окружение и поставит зависимости):
   ```powershell
   .\run.ps1
   ```
5. Откройте http://127.0.0.1:8000 → «Загрузить набор из API» (group_id = `DEV`) → выберите диалоги → «Оценить выбранные».

Linux / macOS: `./run.sh`. Ручной запуск:
```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m uvicorn backend.app:app --port 8000
```

Тесты подсчёта баллов: `.venv\Scripts\python -m pytest -q`

## Что умеет

**Контур 1 — оценка**
- **Чек-лист как данные.** Редактор: критерии, секции, формулировки «Да / Нет / N/A», вес, тип ответа
  (Да/Нет, шкала, флаг нарушения), шкала со ступенями, доступность N/A, пояснения для модели.
  Каждое сохранение — новая версия; оценка хранит версию, по которой сделана. Импорт/экспорт JSON.
  Новый или изменённый критерий применяется без правки кода — промпт и JSON-схема ответа строятся из конфигурации.
- **Загрузка диалогов**: из API организаторов по `group_id` (через сервер, без CORS) или JSON-файлом
  (формат API, список записей или одна запись).
- **Оценка**: очередь в фоне с прогрессом и ETA; RU / KZ / EN; реплики бота и системные события — контекст.
- **Результат**: по каждому критерию — ответ, баллы, базовый и перераспределённый вес, объяснение,
  реплики-доказательства (для пропущенного действия — где ожидалось, для N/A — основание), ход рассуждения модели;
  итог, секции, отметка о грубой ошибке.

**Контур 2 — работа с результатом**
- Карточка: транскрипт + результат; клик по доказательству прокручивает и подсвечивает реплику,
  у звонков — перематывает встроенный плеер на этот момент (▶ у каждой реплики).
- Апелляция по критерию: комментарий + предлагаемая оценка.
- Проверяющий (переключатель роли вверху) видит спорную оценку, комментарий и фрагмент диалога
  с выделенными доказательствами, подтверждает или меняет оценку с причиной → итог пересчитывается.
  В карточке видны исходная оценка ИИ, решение и финальный результат.

**Дополнительно**
- Аналитика: средние баллы, выполнение критериев, распределение, грубые ошибки; экспорт CSV / JSON.
- Сверка с эталонной разметкой (`data/labels/*.json`): точность по критериям и ошибка итога.
- Self-consistency: N голосов модели на критерий, ответ большинством, «уверенность» в карточке.
- Гибрид «правила + LLM» для формальных критериев (приветствие + имя, прощание / обрыв чата):
  правило действует, только пока формулировка критерия не изменена.

## Как считается балл

Строго по разделу «Порядок расчёта» чек-листа, в коде (`backend/scoring.py`), модель баллы не считает:
1. N/A — только где разрешён (ограничено JSON-схемой ответа модели).
2. «Да» = полный вес, «Нет» = 0, шкала = вес × ступень / верхняя ступень.
3. Критерии с N/A исключаются, их вес пропорционально перераспределяется: итог = Σ баллов / Σ весов применимых × 100.
4. Округление до 2 знаков (математическое: 88,125 → 88,13). Нет применимых критериев — итог не рассчитывается.
5. Грубые ошибки — отдельный флаг, на баллы не влияют.

## Архитектура

```
API организаторов ──► backend/datasource.py (прокси, парсинг ссылки на mp3)
                              │
Чек-лист (JSON, версии в SQLite)
   │
   ▼
backend/preprocess.py  — нормализация транскрипта, факты: язык, первая/последняя реплика оператора,
   │                     приветствие/имя/прощание, подтверждение личности, обрыв, паузы, повторы ASR
   ▼
backend/evaluator.py   — по одному вызову LLM на критерий; промпт и JSON-схема из конфигурации критерия;
   │                     ответ ограничен допустимыми значениями; номера реплик проверяются
   ▼
backend/scoring.py     — детерминированный расчёт итога и секций
   ▼
SQLite (data/cqa.db)   — диалоги, версии чек-листов, оценки, апелляции
   ▼
frontend/ (HTML + CSS + ES-модули без сборки) — Диалоги · Карточка · Апелляции · Чек-листы · Аналитика · Настройки
```

### Встраивание в Dynamics 365
Интерфейс — статические файлы без сборки и внешних зависимостей, монтируется в один элемент `#cqa-app`.
Адрес сервиса оценки задаётся через `window.CQA_CONFIG = { apiBase: "https://..." }`, поэтому `frontend/`
можно загрузить как HTML web resource, указав URL развёрнутого backend.

## Модель и стоимость

| | |
|---|---|
| Модель по умолчанию | `qwen3:8b` (Ollama, 4-бит, ≈ 6 ГБ видеопамяти), меняется в «Настройках» |
| Вызовов на оценку | по одному на критерий (формальные критерии могут проверяться правилом без вызова) × число голосов |
| Время | ≈ 40 с на чат на RTX 5050 Laptop 8 ГБ (≈ 2 мин с режимом thinking) |
| Стоимость | 0 ₽ — локальный запуск, токены видны в карточке оценки |

## API (основное)

| Метод | Путь | |
|---|---|---|
| POST | `/api/datasets/fetch` `{group_id}` | загрузить набор из API организаторов |
| POST | `/api/conversations/upload` | загрузить JSON-файл |
| GET | `/api/conversations`, `/api/conversations/{id}` | список, карточка с фактами |
| GET/POST | `/api/checklists`, `/api/checklists/{id}/activate` | версии чек-листа |
| POST | `/api/evaluations` `{conversation_ids, checklist_id}` | запустить оценку (фоновая задача) |
| GET | `/api/jobs/{id}`, `/api/evaluations/{id}` | прогресс, результат |
| POST | `/api/appeals`, `/api/appeals/{id}/decision` | апелляция, решение проверяющего |
| GET | `/api/stats`, `/api/accuracy`, `/api/export.csv` | аналитика, сверка, экспорт |
| GET | `/api/audio/{id}` | редирект на актуальную ссылку записи звонка |

## Сценарий демонстрации (5 минут)

1. **Интерфейс и диалог (1 мин).** «Диалоги» → фильтры по языку / каналу → открыть диалог.
2. **Оценка (2 мин).** Итог и секции; критерий → объяснение → клик по реплике-доказательству (прокрутка и подсветка,
   у звонка — перемотка плеера). Пример N/A (например, клиент покинул чат) и перераспределение веса.
3. **Апелляция (1 мин).** «Оспорить» у критерия → комментарий → переключить роль на «Проверяющий» →
   «Апелляции» → фрагмент диалога → «Изменить оценку» + причина → новый итог.
4. **Изменение критерия (1 мин).** «Чек-листы» → заменить критерий → «Сохранить новую версию» →
   «Применить к диалогам…» → оценка по новой версии, старая сохранена в истории карточки.

Контрольный набор: «Загрузить набор из API» с выданным `group_id` → «Оценить все неоценённые в фильтре».

## Калибровка точности

`python -m scripts.eval_dev [--criteria c07_closing] [--model qwen3.5:9b] [--think] [--votes 3]` —
прогон оценщика по DEV и сравнение с разметкой `data/labels/dev_team_labels.json` (разметка команды по
чек-листу, не эталон организаторов). Печатает точность по критериям, ошибку итога и все расхождения.

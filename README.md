# Team AAA — CQA (Conversation Quality Analytics)

Команда **Team AAA**. Результаты прогонов — в разделе [«Результаты»](#результаты).

Оценка качества работы операторов Freedom Broker по чек-листу. ИИ проверяет чат или звонок (RU / KZ / EN)
по каждому критерию и указывает реплики-доказательства, итог считается в коде. Оценку можно оспорить:
проверяющий подтверждает или меняет её, итог пересчитывается.

Всё работает локально: LLM `qwen3.5:9b` через [Ollama](https://ollama.com), распознавание речи `faster-whisper small`.
Внешних платных API нет; при необходимости в «Настройках» подключается любой OpenAI-совместимый API.

## Быстрый старт (Windows)

1. Установите Python 3.11+ и Ollama, скачайте модель (≈ 6.6 ГБ; видеокарта 8 ГБ — ≈ 40–60 с на чат, на CPU медленнее):
   ```powershell
   winget install Python.Python.3.12
   winget install Ollama.Ollama
   ollama pull qwen3.5:9b
   ```
2. Укажите ссылку на API организаторов: скопируйте `config.local.example.json` в `config.local.json` и вставьте её
   в `org_api_url` (или переменная `CQA_ORG_API_URL`, или «Настройки» → «Источник данных»).
   Подписанная ссылка в репозиторий не попадает.
3. Запустите `.\run.ps1` (первый запуск создаст окружение и поставит зависимости) и откройте http://127.0.0.1:8000.
4. «Загрузить» с group_id `DEV` → выбрать диалоги → «Оценить выбранные».

Linux / macOS: `./run.sh`. Тесты: `.venv\Scripts\python -m pytest -q`.

## Возможности

- **Чек-листы как данные.** Редактор критериев: секция, тип (Да/Нет, шкала, флаг грубой ошибки), вес, условия
  «Да / Нет / N/A», пояснения для модели. Каждое сохранение — новая версия, импорт/экспорт JSON. Отдельные чек-листы
  для чатов и звонков, режим «Авто» выбирает по каналу. Изменённый критерий применяется без правки кода.
- **Оценка.** Фоновая очередь с прогрессом; по каждому критерию — ответ, баллы, вес с учётом N/A, объяснение,
  реплики-доказательства и ход рассуждения; итог, секции, флаг грубой ошибки.
- **Карточка диалога.** Транскрипт и результат рядом; клик по доказательству подсвечивает реплику,
  у звонка — перематывает плеер к этому моменту.
- **Апелляции.** Оспорить критерий с комментарием и предлагаемой оценкой; проверяющий видит фрагмент диалога
  с доказательствами и решает с указанием причины. Видны исходная оценка ИИ, решение и итог.
- **Аналитика.** Средний балл, выполнение критериев, распределение, грубые ошибки, срезы по языкам и каналам;
  экспорт CSV, JSON и `results.json` в формате организаторов.
- **Гибрид «правила + LLM».** Формальные проверки (приветствие и имя, прощание, обрыв чата, обход компании) решаются
  правилом; правило действует, только пока формулировка критерия не изменена.

## Расчёт балла

По разделу «Порядок расчёта» чек-листа, в коде (`backend/scoring.py`) — модель баллы не считает:
1. N/A — только где разрешён (ограничено JSON-схемой ответа модели).
2. «Да» = полный вес, «Нет» = 0, шкала = вес × ступень / верхняя ступень.
3. Критерии с N/A исключаются, их вес перераспределяется: итог = Σ баллов / Σ весов применимых × 100.
4. Округление до 2 знаков (88,125 → 88,13).
5. Грубая ошибка — отдельный флаг, на баллы не влияет.

## Архитектура

```
API организаторов ─► backend/datasource.py   загрузка набора, ссылки на записи
                     backend/preprocess.py   нормализация, факты: язык, приветствие, имя, прощание,
                                             идентификация, обрыв, паузы, удержание
                     backend/autochecks.py   правила для формальных критериев
                     backend/evaluator.py    один вызов LLM на критерий; промпт и JSON-схема из чек-листа
                     backend/scoring.py      расчёт итога и секций
                     backend/audio.py        анализ записи звонка (Whisper, темп, паузы)
                     SQLite                  диалоги, версии чек-листов, оценки, апелляции
frontend/            HTML + CSS + ES-модули без сборки
```

**Встраивание в Dynamics 365.** Интерфейс — статические файлы без внешних зависимостей, монтируется в элемент
`#cqa-app`; адрес backend задаётся через `window.CQA_CONFIG = { apiBase: "https://..." }`. Параметры `?embed=1`
(без боковой панели) и `?role=reviewer` для встраивания в формы.

## Звонки

В контрольном наборе только чаты; для звонков основной источник — транскрипт, запись — дополнительный.

| Что сделано | Зачем бизнесу |
|---|---|
| Тот же конвейер, отдельный чек-лист звонков (06 — логичность, формулировки, паузы) | Один инструмент для всех каналов; новый чек-лист — без разработки |
| Из записи — темп речи, разборчивость, паузы вне удержания; передаются модели как факты | Оценка 06 опирается на измерения, которых нет в транскрипте |
| Клик по доказательству перематывает запись к моменту | Проверяющий слушает спорный фрагмент, а не весь звонок |
| Разговор с коллегой на удержании — внутренняя консультация | Оператора не штрафуют за консультацию — меньше апелляций |
| Распознавание локально на CPU, модуль отключаемый | Записи не покидают контур компании; видеокарта остаётся для LLM |

## Трактовки чек-листа

С учётом ответов организаторов:
- **07** — буквально: итог **или** предложение помощи **и** прощание. Вежливая формула с прощанием
  («Пожалуйста. Хорошего вечера!») — «Нет». N/A — только если чат оборвался до возможности его завершить.
- **02** — клиент сразу дал все детали (в т. ч. боту), оператор ответил без уточнений — N/A.
- **03 / 08** — данные счёта раскрыты до идентификации: 03 «Нет» и 08 «Да».

## Сдача результатов

`results/dev/results.json` — DEV, `results/prod/results.json` — контрольный набор (формат JSON 1.0 организаторов:
`evidence_turns` с 1 по исходному транскрипту, `final_score` с перераспределением при N/A, неоценённый диалог —
`status: "error"`). Выгружаются ответы системы без решений по апелляциям.

Контрольный набор — одна команда при запущенном сервере: загрузка, оценка, повтор неудачных, выгрузка,
проверка формата и ID, commit и push.
```powershell
.venv\Scripts\python -m scripts.control_run --group-id <ID> --target prod --push
```

## Результаты

| Набор | Файл | Итог |
|---|---|---|
| Контрольный FBroker, 10 чатов | `results/prod/results.json` | 10 из 10 оценены, формат и ID проверены |

Один чат: ≈ 31 с, ≈ 14 тыс. токенов, платных API нет (среднее по 70 чатам, видеокарта ноутбука 8 ГБ).

Где смотреть: в интерфейсе «Аналитика» → выбрать набор (сверка с разметкой, кнопка `results.json`);
`GET /api/accuracy?dataset=DEV`; полный прогон с расхождениями — `python -m scripts.eval_dev`.
